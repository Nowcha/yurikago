# 受け入れテスト手順書（初回セットアップ後）

前提: `npm install` 済み、`src/lib/store.ts` の firebaseConfig 貼り替え済み、firestore.rules デプロイ済み。
所要目安: 30〜40分。夫のPC＋妻のスマホ（または2つのブラウザプロファイル）で実施。

## A. 自動テスト
- [ ] `npm test` → deadline計算 全ケースPASS
- [ ] `npm run test:rules` → ルール 全ケースPASS（Java必要。失敗時はEmulator未起動を疑う）
- [ ] `npm run build` → 型エラーなくビルド完了

## B. セットアップ・世帯
- [ ] `npm run dev` → Googleログインできる
- [ ] 予定日＋プロファイル2項目を設定し世帯作成 → タスクが自動生成される
- [ ] プロファイルのチェックを外して作った場合、該当手続き（出産手当金等）が「対象外」で生成される（別世帯で確認→テスト後削除）
- [ ] 【重要】もう一方の端末でログイン → 参加待ち画面に自分のUIDが表示される
- [ ] 先の端末の「設定 > 世帯 > パートナーを追加」でUID登録 → 相手の画面が数秒で世帯表示に切り替わる
- [ ] 第三のGoogleアカウントでログインしても世帯が見えない（ルール検証）

## C. タスク（夫婦同期の本丸）
- [ ] 一方がタスクを「完了」→ 他方の画面に即時反映される
- [ ] 担当を割り当てるとバッジに表示名が出る
- [ ] 出生届の詳細に準備サブタスク4件が出て、チェックが同期される
- [ ] 「生まれたら期限が決まるもの」セクションに産後手続きが期限なしで並ぶ
- [ ] 手動タスクを期限付きで追加 → タイムラインの正しい位置に入る → 削除できる
- [ ] 公式リンク（江東区・018サポート等）が開ける

## D. 出生イベント（テスト用データで実施）
※本番世帯では出産まで実行しないこと。確認する場合は世帯削除→バックアップ復元を使う
- [ ] 設定の「生まれたら」で出生日登録（2段階確認あり）
- [ ] 出生届の期限が「出生日+13日」、児童手当が「出生日+15日」になっている（起算日が異なるのが正しい）
- [ ] ダッシュボードが「生後◯日」表示に切り替わる

## E. 準備品
- [ ] チェックで実費入力欄が出る → 予算/実績の集計に反映
- [ ] 「不要」で予算集計から除外される
- [ ] 「産後に様子見て」バッジが抱っこ紐等に付いている

## F. データ管理・PWA
- [ ] JSONバックアップ → 世帯削除 → 新規世帯作成 → 復元、で内容が戻る
- [ ] ICSエクスポート → スマホのカレンダーに法定期限が入る（3日前アラーム付き）
- [ ] GitHub Pagesデプロイ後: スマホで「ホーム画面に追加」→ アイコン表示・スタンドアロン起動
- [ ] 一度読み込んだ後に機内モード → アプリが起動し、タスクの閲覧・編集ができる → 復帰後に同期される
  （注: SWはstale-while-revalidate方式のため、アプリの更新は「次回起動時」に反映される仕様）

## G. 週次情報（Phase 1.5）
- [ ] ダッシュボードに現在の週の「今週の赤ちゃん」カードが表示される
- [ ] 記載内容を母子手帳・産院資料と突合してレビュー（weekly-info.jsonはドラフト）

## H. 育児記録（出生日登録後）
- [ ] 出生日登録後、タブ先頭に「きろく」が出現する
- [ ] 母乳左をタップ → 即記録され「前回の授乳から」が0分にリセット
- [ ] ミルクをタップ → 量入力シート → 記録一覧にml表示
- [ ] 「ねた」→ボタンが「おきた」に変わる（睡眠状態のトグル）
- [ ] 一方の端末の記録が他方に即時反映される
- [ ] 機内モードで記録 → 復帰後に同期される（深夜の産院を想定した最重要ケース）
- [ ] JSONバックアップにrecordsが含まれる
